# Google Docs & Technical Writing Basics

## 1. Basics of Technical Writing

Technical writing is about communicating technical ideas, instructions, and reports clearly and simply. The goal is to make information easy for the reader to understand without confusion.

### Key Rules We Learned
1. **Be Clear and Direct**: Use simple, straightforward words. Avoid unnecessary complicated words or fluff.
2. **Be Concise**: Say what needs to be said in fewer words without leaving out important technical facts.
3. **Use Active Voice When Possible**:
   - *Better (Active)*: "The function calculates the shortest path."
   - *Less direct (Passive)*: "The shortest path is calculated by the function."
4. **Organize Logically**: Use clear headings, bullet points, and numbered lists so the reader can scan and follow easily.

---

## 2. Standard Structure of a Technical Report

In engineering and lab courses, reports usually follow this structure:

1. **Title & Author Details**: What the report is about and who wrote it.
2. **Abstract**: A short summary (one paragraph) of the problem, what was done, and the main result.
3. **Introduction**: Explains the background, what problem is being solved, and why it matters.
4. **Methodology / Implementation**: Explains the step-by-step approach, tools used, and how the task or code was implemented.
5. **Results & Observations**: Shows what happened (using tables, charts, or output screenshots).
6. **Conclusion**: Summarizes what was achieved and mentions any future improvements.
7. **References**: Lists where information or source material was taken from.

## 3. Using Google Docs for Collaborative Work

While final academic papers are often compiled in LaTeX, **Google Docs** is great for writing initial drafts, collaborating in team projects, and reviewing each other's work.

### Important Features for Technical Teams

- **Real-Time Collaboration**: Multiple students can work on different sections of the same document at the same time.
- **Editing Mode vs. Suggestion Mode**:
  - *Editing Mode*: Any changes you make directly modify the document.
  - *Suggestion Mode*: Useful during peer review. Any change you make appears as a suggestion (like track changes in Word). The main author can accept or reject it with one click.
- **Comments and Mentions**:
  - You can highlight any sentence or paragraph and click **Add Comment**.
  - Type `@email` or `@name` to assign a specific task or question to a team member.
- **Version History**:
  - Google Docs automatically saves every edit.
  - You can view past versions (`File > Version history > See version history`) and restore an earlier version if someone makes a mistake.
  - You can name important versions (like "Draft Before Lab Evaluation").
- **Heading Styles & Table of Contents**:
  - Marking text as `Heading 1`, `Heading 2`, and `Normal text` creates an outline on the left sidebar.
  - You can insert an automatic Table of Contents with clickable links to all sections.
